# Gameplay specification edit scope

These files define normative game behavior. Prefer correcting the relevant original chapter in place. Cross-check upstream and downstream chapters, acceptance scenarios and task routing. Do not create a competing gameplay rules file, append a contradictory historical note into normative text, or change agreed gameplay merely to simplify implementation. A genuine design amendment requires the change process in `docs/agents/CHANGE_CONTROL.md`. Preserve numbered chapter IDs; don't renumber them as it breaks task routing.
