## SOV-P01-T03 — Minimal native desktop executable
`godot --path game -- --fixture F-EMPTY` opens a 1600×900 window running a fixed-step update loop over one `World`, at one simulated second per real second with at most 10 steps per frame (`game/src/Simulation/SimulationHost.cs`). The window close request, Ctrl/Cmd+Q and `--quit-after` all run one idempotent shutdown: log the checksum, write `--record`, flush logs, exit code 0.

Evidence:
- headless `--verbose` run: exit 0, no leaks;
- windowed run on macOS: captures below;
- client test "close request and quit action each log the shutdown checksum and request exit".

Limitation: a real OS close button and keyboard chord were not clicked by hand. They were exercised through Godot's notification and input-event paths in tests. **State:** Ready for review.

## SOV-P01-T07 — Automated build, tests, lint and packaging smoke
`.github/workflows/build.yml` has four jobs:
- `simulation`, on Ubuntu, Windows and macOS: locked restore, format check, Release build with warnings as errors, tests, content validation, fixture determinism;
- `client`: pinned and SHA-512-verified Godot, import, C# build, client tests, shell launch with the leak check;
- `determinism`: compares the per-OS `F-EMPTY` results (ADR-0004 §3 measurement);
- `package`: runs on every PR, on `main` and on manual dispatch. It exports Linux, adds the content and generated notices, then runs the packaged binary and requires "world created" and "shutdown".

The shell smoke requires "world created" and "shutdown", and forbids engine `ERROR:` lines and leak lines, so a launch that never creates a world fails.

All actions are pinned by commit SHA, with read-only permissions. `.github/rulesets/protect-main.json` requires `docs`, the three `simulation (...)` checks, `determinism`, `client` and `package`. `validate_repo.py` now expands matrix job names when checking it.

Local equivalents pass (table above). GitHub-hosted runs are pending. **State:** In progress (needs a pushed run).

## SOV-P01-T09 — Failure report
`FailureReport` records the reason, exception, build, seed, scenario, simulation time, state checksum, full command journal, recent host input actions (`HostInputEvent`) and recent log records.
- **Writers:** the headless runner on any simulation exception, and on `--fail-at-ms`; the client on a step or submit exception, on F9, and from the AppDomain handler.
- **Replay:** `sovereigns-headless replay <report>` rebuilds the world and compares checksums (exit 3 on mismatch).
- **Failing step:** when a step throws part-way, the report records the completed steps and every input of the failing step, and replay re-runs that step to reproduce the exception.
- **File names:** a later report from the same seed and time is written alongside the original, not over it.
- **Tests:** a report written and replayed; a tampered checksum and a tampered command, each reported as mismatch exit 3; a failing step reproduced; unique file names; the client's injected failure replayed to the same checksum.

**State:** Ready for review.

## SOV-P01-T10 — Reusable 2D orthographic inspection shell
`game/src/View` and `game/src/Ui` provide:
- **View:** world metres converted to the screen with y flipped, in double precision, using float32 only relative to the camera centre (ADR-0004 §2). Pan and zoom anchor at the cursor, a fit command shows the world, and the grid adapts from 10 m to 10 km (by zoom) with a scale bar and north arrow.
- **Layers:** 17 layers. "World frame and grid" and "Developer markers" are available. The 15 unimplemented §3.2 families each show a hatched no-data overlay and the banner `No data — <owner> implements this family in Phase NN`.
- **Location inspector:** re-queries `World.Inspect` every 0.25 s and greys unavailable readings with their reason.

Client tests cover the view math, layers and inspector. Windowed captures confirm legibility. **State:** Ready for review.

## SOV-P01-T11 — Debug HUD and launch documentation
The HUD shows the real seed and fixture, scenario, simulation time and steps, step size, and active world chunk, with the camera centre and metres per pixel. It also shows FPS, frame time, step cost, managed heap, Godot static memory, orphan nodes, warning and error counts with the last warning, journal and pending commands, the state checksum and the build.

[game/README.md](../../game/README.md) documents one launch command, seed and scenario selection, and inspection steps.

Inspector values are numbers with SI units. The client formats them; the simulation does not (ADR-0004 Consequences).

**Deviation:** "active world chunk" reads `unavailable — chunking arrives with SOV-P03-T07`. No chunk scheme exists before Phase 03, and inventing one would fabricate a contract. **State:** Ready for review.

## SOV-P01-T12 — Input actions, rebinding foundation, deterministic command capture
- **Actions:** `InputActions` defines 16 named actions with defaults, registered in Godot's `InputMap` by code.
- **Rebinding:** `InputBindings` loads and saves the versioned file `{"version": 1, "bindings": {...}}` (overrides only). It rebinds, finds conflicts, and skips malformed entries or unsupported versions with warnings. There is no rebinding UI (Phase 48).
- **Command capture:** world-changing actions become `SimCommand`s, which the world applies at step boundaries and journals with sequence, time and any rejection. `CommandJournal` reads and writes JSON lines, and `Replay` rebuilds and verifies.
- **Evidence:** a client journal replays in the headless runner to the identical checksum (client test, and a manual run by the client worker). `ReplayTests` pins the JSON format and the rejection of malformed journals.

**State:** Ready for review.

## SOV-P01-T13 — Content schema validation
`ContentCatalog.Load` validates content layout and IDs: path and ID agreement, the `namespace:kind/name` format, and kinds and stray files. It also checks the strict JSON schema (unknown, missing, mistyped and null members), the semantic rules, and references (existence, kind, did-you-mean). Every error names the file, line or JSON path, and the fix.

`ContentTests` has 27 cases (hidden files such as `.DS_Store` are ignored), `sovereigns-headless validate-content` runs in CI, and the documentation is in [content/README.md](../../content/README.md). Only the `scenario` kind exists in production. Reference validation is exercised by test kinds (commodity and recipe), because no production kind has references yet. **State:** Ready for review.

## SOV-P01-T14 — License and attribution tracking
